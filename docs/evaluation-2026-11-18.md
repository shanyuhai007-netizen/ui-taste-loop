# 首次全流程实测：评审分数为何不向上收敛（2026-11-18）

对一次真实产品改版（4 页面：登录/列表/详情/控制台）跑完整三阶段流程的复盘。
五轮 fresh-context critic 循环，分数轨迹 **7.2 → 8.0 → 7.5 → 7.6 → 8.3** 呈锯齿。

## TL;DR

分数不收敛的根因不在实现质量，在**测量协议**。四个机制（按证据强度排序）：

| # | 机制 | 判定 |
|---|---|---|
| 1 | 每轮换 fresh critic + 绝对分无锚定 → 裁判间方差 ±0.5~1.2 淹没每轮 +0.3 的真实改进 | ✅ 冻结页实验证实 |
| 2 | 反馈向量场不一致：修 A 生 B（密码框：R3 要求加 placeholder → R4 批评该 placeholder） | ✅ 闭环证据 |
| 3 | prompt 强制每页 3-6 条问题 → 缺陷耗尽后 critic 下沉到品味偏好/产品建议，分数被格式性封顶 | ✅ 计数证实 |
| 4 | 模型对截图先做文字转述再评审，转述在协议层被截断 | ⚠️ 降级：像素已原生入上下文，失真程度无法确证 |

「连续 2 轮不涨交人裁决」被验证有效。**结论：polish 修不掉的扣分项，往往是人才能拍板的决策。**

## 实测数据

| 轮 | 总分 | 登录 | 列表 | 详情 | 控制台 | 问题条数 |
|---|---|---|---|---|---|---|
| R1 | 7.2 | 7.2 | 6.9 | 7.1 | 7.9 | 22 |
| R2 | 8.0 | 8.5 | 8.0 | 7.5 | 8.2 | 23 |
| R3 | 7.5 | 7.5 | 7.8 | 6.8 | 8.2 | 21 |

问题条数恒定而分数锯齿 → 分数波动的主导变量是**裁判身份**，不是缺陷数。

### 冻结页自然实验（逐像素 diff）

各轮截图逐像素 diff（变化像素占比，Δ≥8 阈值）：

| 轮对 | login | home | detail | console |
|---|---|---|---|---|
| r1→r2 | 6.20% | 1.77% | 1.21% | 0.57% |
| r2→r3 | 4.89% | 0.44% | 0.20% | 0.18% |
| r3→r4 | 4.94% | 0.15% | 5.31% | 0.08% |
| r4→r5 | 0.02% | 0.11% | 9.22% | 0.00% |

- r2→r3：home/detail/console 近乎冻结（<0.5% 为演示数据 churn），换裁判后分数 **-0.2 / -0.7 / 0.0**。最干净样本：R2 与 R3 都把同一个结构问题列为详情页第 1 号，同一缺陷一个判 7.5、一个判 6.8
- r4→r5：login/home/console 冻结，分数 +0.2 / +1.2 / -0.2；detail（人工裁决撤掉一个小节，9.22% 变化）+1.1。**冻结页上的 ±0.2~1.2 漂移就是裁判间方差的直接测量**

## 四个机制

1. **换裁判 + 无锚定绝对分**：fresh critic 每轮自造量表（无锚点样例），绝对分跨轮不可比。
2. **反馈向量场不一致**：不同裁判的改进方向互相矛盾，对该向量场做梯度下降必然震荡。最硬的闭环：R3 要求「加 placeholder」→ 修复落地 → R4 批「该 placeholder 同义重复，改提示文案**或直接留空**」——「留空」恰好回到 R3 批评的状态。不可修项同理：被设计契约禁止的写法被 3 轮重复扣分；待人工裁决的结构问题被 4 轮重复扣分（循环内无权修 → 分数天花板）。
3. **格式性封顶**：「每页 3-6 条问题」保证问题永不归零，被义务要求找问题的裁判不会打 9。缺陷耗尽后的产出物示例：「静态图无法确认 tabular-nums 是否生效」（无法验证项）、产品 roadmap 建议（非视觉缺陷）。
4. **转述层（降级）**：critic 的 transcript 显示截图确实以原生图像进入模型上下文；但模型对每图又自发调用服务端图像转述工具先转述再评审，且转述在协议层被截断（描述断于半句）。失真程度无法确证，作为环境观察保留，对应的防线是 prompt 明写「直接基于像素评审」。

## 做对了什么（保留）

- 「连续 2 轮不涨交人裁决」精确触发；用户裁决撤 1 个元素后单页 6.8→8.6——唯一含裁决的轮次拿到最大涨幅，且涨幅集中在被裁决的页面上
- 停止线（9/10）五轮均未漏进 critic prompt；fresh-context、只喂截图均保持
- R1→R2 +0.8 说明 polish 在快赢阶段有效；失效的是第二段（快赢修完后边际收益归零）

## 对首版复盘的事实核查更正

- ❌「critic 从未直读像素」→ transcript 证实图像原生入上下文（转述为模型自发叠加层）
- ❌「某页两轮之间只有小改」→ 像素 diff 证明改动量与上一轮相当，已用冻结页实验替换该证据
- ⚠️「R5 涨幅全来自裁决」→ 降为强相关（同轮含其他修复）
- ⚠️「某轮 token 消耗高因追加核对」→ 删除（归因不成立）

## 落地修订（即本仓库当前 SKILL.md）

1. 评分协议：R2 起新旧两版同评，A/B 判决（更好/持平/更差 + 新增问题）为主信号，绝对分降为趋势记录，固定等权平均
2. 退出条件：裸 9/10 改为复合条件（「无新增缺陷」+ 多数页「更好」，或 8.5±0.5 带内无新增缺陷）
3. 问题条数 3-6 改 0-6 且强制分类（[缺陷]/[裁决]/[偏好]），解格式性封顶 + 天然形成待裁决清单
4. 豁免清单：契约禁项/已裁决保留项/静态盲区三类，循环开始一次性导出（实测逐轮打补丁会从 2 条无界增长到 7 条）
5. prompt 明写「直接基于像素评审、不调用转述工具」

修订后协议待下次 UI 票实测对照验证。
