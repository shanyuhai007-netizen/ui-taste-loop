# Critic Prompt——评审载荷与豁免清单

Phase 2 的 critic 载荷单点维护。使用规则（fresh-context subagent、只喂截图、每轮换裁判、R2 起锚定对比、双视口截图协议）见 [SKILL.md](../SKILL.md) Phase 2。

## Critic 派生层级（隔离优先）

评审者与实现者的隔离质量决定 critic 信号的可信度——实测同实例降级运行中，critic 回复直接引用了实现侧的 diff 矩阵（隔离破防）。按序取第一个可用档，禁止跳档：

1. **主会话派生**（首选）：在具备 Agent 工具的主会话里派生 fresh-context critic subagent，只传截图文件与评审 prompt，不传代码/实现说明/轮次历史。
2. **上报主控派生**：身在无派生能力的子代理内（嵌套被调用）时，不要就地自评——把 critic 环节连同截图清单上报主控会话，由主控按第 1 档派生后回传判决。禁止「子代理里自己换个角色评自己」。
3. **同实例硬隔离**（最后手段，确认无任何派生与上报通道才用）：同实例切换角色，但输入必须硬隔离——只允许 Read 截图文件；明令禁止读实现代码、diff 矩阵、改动说明、token 契约与轮次留档；prompt 不携带任何实现信息。降级档位必须记入留档（process.md 标注「critic=同实例硬隔离」），该轮评审按低可信信号处理，收口判断从严。

外部 CLI（codex exec 等）仅作备注：环境确知有额度/订阅时可作第 3 档的等价替代（fresh 隔离优于同实例降级），但不替代第 1-2 档的派生，也不进主路径——不得因「可能可用」而省略隔离纪律。

## 视觉输入保真阶梯

critic 拿到的视觉输入按保真度取最高可用档，每降一级必须在留档标注实际通道（实测：图像通道不稳定时被迫降到几何投影，属评审转述层失真的更硬形态）：

1. **原生图像入上下文**：截图文件经 Read 进入 critic 上下文，直接基于像素评审。
2. **图像分析工具**：vision 类工具读图；注意可能 403 或只回 CDN URL，用前先验证一次调用。
3. **几何测量投影**（保底）：headless 浏览器量取元素几何（位置/尺寸/字号/颜色计算值）+ 布局投影图；只能支撑布局/间距/对齐类判断，色彩与字体观感须明示「本通道不可评」，不得装作评过。

## Prompt 模板

```
你是顶级设计工作室的设计总监，评审一个产品的新旧两版界面截图（桌面全页按产品流程排列，另附关键页的移动 375px 截图）。
- 截图经 Read 已在你的上下文中，直接基于像素评审；不要再调用图像转述/分析工具
- 先独立评新版，再做两版对比（同视口对比：桌面比桌面、移动比移动）：
  1) 逐页 0-6 条问题（可为 0，无重大缺陷要明说），按六个维度归类陈述——
     布局与视觉层次 / 排版与字体 / 间距与对齐 / 色彩 / 组件与细节工艺 / 文案。
     维度是组织轴不是打分轴：允许整维 0 条，不硬凑。
     每条标类别、指到具体位置、给可执行修改：
     [缺陷] 视觉/实现层面，可直接修 ／ [裁决] 结构/产品决策，人定 ／ [偏好] 品味取向，可不采
  2) 逐页判决：新版更好/持平/更差 + 一句话理由；单独列出新版引入的问题；移动视口的问题单独标注
- 兼顾整体构图与微观细节（间距、字阶、对齐、色彩层次）
- 识别并惩罚「用力过猛/明显 AI 味」：紫青弥散光晕、渐变描边、万物容器化、
  全面药丸圆角、无动机的漂浮小标签、模板化左文右图 hero、营销腔文案
  （buzzword/空形容词——具体性应来自数字与实物）、对仗警句反复出现
- 大胆有立场，不选安全牌；想象顶级工作室会怎么执行这个美学，指出与它的最大差距
- 豁免清单（不要再提、不据此扣分）：<循环开始时一次性导出，见下>
- 末行输出各页等权平均分 `X.X/10`（以桌面截图计，固定等权，仅作跨轮趋势参考）
```

模板设计要点：六维组织是防 critic 缺陷耗尽后下沉到品味偏好的手段，不是打分轴；停止线（9/10）与收口条件不写进 prompt，保持裁判客观。首行「截图经 Read 已在你的上下文中」为第 1 档（原生图像）措辞——降到第 2/3 档时改写为实际通道说明，并按「视觉输入保真阶梯」在留档标注。

## 豁免清单

循环开始时一次性写进 prompt 固定段（替换模板占位符），三类来源：

1. **契约禁项**：设计契约明令禁止的写法
2. **已裁决保留项**：人拍板保留的
3. **静态盲区**：hover/sticky 等已实现但截图看不到的

critic 重提即忽略；被拒的新建议经人裁决后补进清单。不逐轮往 prompt 里打补丁——实测补丁无界增长（2 条 → 7 条）且只治症状。

## 状态抽查（收口前，一轮即止）

票内涉及空态/错误态的，收口前各截一张图单独送评，prompt 只需一句：「只判这些状态是否达到主界面同一 craft 水平」。不进循环、不产生新轮次。

## 评分协议依据

绝对分跨裁判不可比（实测裁判间方差 ±0.5~1.2，淹没每轮 +0.3 的真实改进），可比信号只有同一裁判眼里的新旧两版 A/B 判决；绝对分仅作跨轮趋势记录。数据与四机制分析见 [docs/evaluation-2026-11-18.md](../docs/evaluation-2026-11-18.md)。
